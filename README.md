# Stormworks Stippler

A local upload/download tool that adds lighter and darker paint variations to Stormworks vehicle XML files. Requires Python 3.10 or newer; no third-party dependencies.

Preview and conversion run entirely in the browser; files are not uploaded to a server. The converter is bundled into the single HTML file so embedded previews do not need to load separate JavaScript assets. You can also open `web/index.html` directly or host the contents of `web/` on a static site. The Python server is an optional local file server with a separate conversion API. The browser and Python converters each reproduce their own output for a given seed; their random sequences differ.

Run `python3 server.py` from this directory, then open `http://127.0.0.1:8000` in your browser. Choose a vehicle XML, adjust the strength, and download a separate `-stippled.xml` file. Your original is never overwritten. The same seed and settings produce the same output.

Strength is the maximum random offset per RGB channel (0–50). Each selected paint slot gets its own random shade offset. Individual faces on wedges and other blocks can vary independently, with RGB channels clamped to 0–255.

In **Vary selected paint colors** mode, every supported source color is listed with a swatch, occurrence count, and unchecked checkbox. Only checked colors are changed, and only those colors get preview cards; there is no three-color preview limit. A new upload resets the selection. Select at least one color to enable download. Each preview shows the original swatch and sample output shades. It updates with strength and seed. Ranking counts supported paint-color occurrences, including individual face colors, rather than visible surface area. The tiles sample colors from the actual conversion; their arrangement is illustrative and does not reproduce vehicle geometry or game lighting.

Choose **Replace one paint color** to select any supported color found in the uploaded creation. Click a palette title to select it. **Add color** inserts a neutral-gray swatch into the selected palette; click any swatch to open its native color editor. Replacement colors appear as swatch cards; use the × button on a card to remove that palette entry. A scored-seed generator paints orthogonally connected blobs over a canvas filled with the first palette color, processing colors in palette order. Each matching paint slot gets independent shade variance, and sparse contrasting outliers can interrupt a blob. Exact matches are case-insensitive. Other colors remain unchanged. Strength 0 uses the replacement colors exactly. The selected color appears first in the preview, followed by common unchanged colors. The selected-color preview runs a complete 50×50 flat-grid simulation using the same XML converter, growth algorithm, and settings as export. It preserves the generated spatial arrangement instead of shuffling color samples; the vehicle’s actual geometry can produce a different layout. The same seed and settings reproduce the result. This mode is available in the browser interface; the separate Python API remains the all-color variation converter.

Every source color has a clickable swatch beside its hex code and occurrence count. The previous preview stays visible until the next valid result is ready.

Replacement mode displays **Desert camo**, **Woods camo**, and **Arctic camo** side by side (stacked on narrow screens). Click a title to select the active palette, highlighted in green. All palettes can be edited independently, including inactive palettes, without switching the active selection. Adding inserts a default #808080 swatch into the active palette; editing or deleting changes only that swatch’s palette. Switching palettes updates the conversion preview. Previously customized palettes are preserved; untouched old default palettes are upgraded to the camo presets. All three palettes and the active palette selection are saved automatically in local browser storage and restored on reload. They are specific to this browser and website origin, and clearing site data removes them. If storage is unavailable, editing still works for the current session and the interface reports that it cannot persist changes.

### Advanced replacement options

This feature branch uses finite paint-tile graphs, scored seeds, and connected growth instead of the earlier noise-based blobs.

- **Seed spacing (previously frequency):** target shortest-path distance in tiles to the nearest same-color seed. New seeds must be within ±2 tiles of that distance (minimum distance 1). 0 disables an overlay color; the first color is always the base. Larger values spread seeds farther apart. The first seed of each disconnected tile component has no same-color spacing restriction.
- **Blob size:** target average tiles owned and grown by each seed, 1–512. Same-color tiles already on the base canvas do not count until adopted by that blob, and neighboring blobs are not counted as part of it. A centered uniform stopping distribution varies sizes around the target; bounded running-mean correction compensates for prior shortfalls. An open-map regression check requires the average to stay within one tile of a requested size of 24. Boundaries, reserved seed anchors, and small regions can force shorter blobs, so the average cannot be guaranteed on arbitrary finite geometry. Later colors can also overpaint and shrink the final visible regions. The tile-map preview reports grown averages and boundary-limited counts.
- **Other-color seed repulsion:** weights a penalty for proximity to existing other-color seeds. Score = same-color spacing error + repulsion × the sum of `1 / (1 + nearest other-color seed distance)` for previously seeded colors. Every valid candidate receives weight `1 / (1 + score)` and the next seed is drawn randomly in proportion to those weights. Lower scores are more likely, but higher-score valid spots can still win. The ±2-tile spacing constraint still applies, and the random seed makes results repeatable.
- **Growth strictness:** 0–1, saved per palette. 0 preserves uniform random connected-frontier growth. Between 0 and 1, a candidate at distance `d` receives weight `exp(-s / (1-s) × (d - nearestDistance))`, favoring tiles closer to the blob's seed as strictness `s` increases. At 1 only minimum-distance frontier tiles are eligible, with random tie-breaking. Distance follows orthogonal paint-tile links. Seed placement and stopping probabilities are unchanged.
- **Outliers:** optional 0–10% contrasting paint spots after growth (default 5%, or probability 0.05). Seed anchors are protected. Shade variance applies independently to each paint slot.

The starting canvas uses the first palette color, with the usual per-slot shade variance. Its spacing and blob-size controls are disabled and it does not generate seeds. The remaining colors generate from top to bottom in palette order. Use the ↑ and ↓ buttons on swatches to reorder a palette: the first swatch is always the base, and each color’s spacing and blob-size settings move with it. Reordering is saved, including when editing an inactive palette; color pickers remain editable for all swatches. A palette with only its base, or with all overlays disabled, produces a base-color fill. Each seed grows its own connected region by selecting an unclaimed frontier tile next to a tile owned by that seed. Tiles of the same color on the starting canvas can be adopted, but each tile counts only once for that blob. Different blobs cannot claim one another’s tiles during a color pass. Later colors can overpaint earlier growth, while all seed tiles remain reserved. A color finishes only when there are no valid seed positions. Each new seed reserves a fresh tile and each growth step claims a fresh tile for that pass, guaranteeing finite progress. Disabled overlay colors never enter the canvas or outliers; the base color remains available regardless of its disabled spacing setting.

### Tile map and preview

The XML supplies block positions and paint-slot indices, but not a complete catalog of block meshes. The generator uses one body-local growth graph shared by base, accent, and face-paint slots. Orthogonal neighbors are matching positions one voxel apart in the same body. Positions without any selected paint slots are holes in that graph. Overlapping positions share a growth tile; the preview still separates the exported paint slots into layers. Paint slots without safe integer positions are isolated tiles and are reported; no geometry is invented for them.

**Paint tile map** previews the exact target-color tiles written to the XML. Select a body/slot layer, an X/Y/Z slice axis, and a slice position. Dots mark seed anchors. Colors include the generated variance and outliers. These slices are not an unfolded surface net: reliably unfolding wedges and other custom blocks requires block geometry and face-index mapping that this repository does not yet provide. The 50×50 simulation remains separate from this actual-vehicle layer view; it previews growth on a complete flat grid rather than the vehicle’s holes and disconnected regions. Vary-selected shade previews remain unchanged.

Seed-growth palettes use `stormworks-stippler.seed-growth-palettes.v1` browser storage. Existing palette colors are imported from the previous blob or live version, but their density/diameter settings are not reinterpreted. Defaults are spacing 8 tiles, connected size 10, growth strictness 0.5, repulsion 2, and outliers 5% (probability 0.05). Each palette saves its settings independently in the browser, including on first load. Existing saved settings are preserved.


The format adapter handles one- to six-digit hexadecimal `bc`, `ac`, `bc2`, and `bc3` paint attributes and `sc` face-color lists on `<o>` elements within a `<vehicle>` document. Omitted leading zeros are restored for display and color matching (for example, E232 is #00E232). Unchanged XML values retain their original spelling. Face-list count markers are preserved. Count-only face lists (2–64 slots) inherit the original base color for matching and counting; when changed they are expanded into explicit independently randomized face colors. An unchanged count-only list retains its original XML spelling. It preserves other XML text, including comments, whitespace, and declarations. A file with no supported colors produces an error. Unsupported attribute formats remain unchanged. Validated against the supplied Medium Tank XML for paint changes and preservation of non-paint data; an in-game import check is still needed. Keep a backup of your creation.

Run tests with `python3 -m unittest discover -s tests -v`.

Browser regression checks require Playwright and Chromium: run `node tests/browser.cjs`. Set `CHROMIUM_PATH` if using a system Chromium installation instead of Playwright's bundled browser.

## Live website

The GitHub Pages workflow in `.github/workflows/pages.yml` tests the converters and deploys only the static `web/` directory on every push to `main`. The blob feature branch and pull requests run validation only. Deployment is restricted to `main`, including manual runs, so testing the branch cannot replace the live site. The main workflow can also be run manually from the Actions tab. No backend, API keys, or upload storage are needed; XML files stay in the visitor's browser.

One-time repository setup: open **Settings → Pages**, then set **Source** to **GitHub Actions**. After the workflow completes, the expected website address is `https://jpflei.github.io/Stormworks-Stippler/`. The deployment job reports the actual URL. If the repository is private, GitHub Pages availability depends on the account plan.

If Pages is configured to deploy from the `main` branch root instead, the root `index.html` forwards visitors to the app in `web/`, preventing the README from becoming the homepage. GitHub Actions remains the recommended source because it runs checks before publishing.

The server binds to loopback by default. For a cloud host that provides its own authenticated port access, use `python3 server.py --host 0.0.0.0`. Do not expose it directly to the public internet.

Paint slots on the same body share one spatial blob field, so rotated blocks and different face slots follow the same patches. Per-slot shade variance and outliers remain independent. A layer preview shows only the selected paint slot and slice, rather than the fully rendered vehicle.
